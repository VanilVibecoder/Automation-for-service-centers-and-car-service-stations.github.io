# Ограничения MVP

## Нужно учитывать сейчас

1. Полный SQL schema/functions dump не включён: его нужно экспортировать из исходного PostgreSQL.
2. `FAQ`, `status_request` и текстовый маршрут `unsupported` присутствуют в классификаторе, но не входят в текущий портфолио-scope.
3. Изменение существующей заявки передаётся сотруднику. Бот не изменяет конкретную заявку автоматически.
4. При нескольких активных заявках оператор уточняет нужный номер.
5. Голос, фото, документы и геолокация не распознаются; клиент получает просьбу написать текстом.
6. Каталог, зоны, цены и слоты — демонстрационные данные.
7. Ollama должен быть доступен из контейнера n8n.
8. Нет отдельного redelivery-worker для периодической повторной отправки `pending/failed`.
9. Нет централизованных алертов и dashboard по ошибкам.
10. Telegram — единственный реализованный канал.

## Полезно позже

- FAQ/RAG;
- статус заявки;
- выбор существующей заявки клиентом;
- автоматический перенос/отмена заявки;
- STT для voice;
- OCR/vision для фото;
- SLA-алерты;
- dead-letter queue;
- multi-tenant admin panel;
- CRM/1С-интеграция;
- метрики конверсии и времени ответа.

## Не нужно добавлять в портфолио-версию

- сложный multi-agent;
- отдельный векторный поиск для маршрутизации заявки;
- Kubernetes;
- микросервисы ради количества компонентов;
- автоматическую генерацию ответов там, где достаточно правил.
